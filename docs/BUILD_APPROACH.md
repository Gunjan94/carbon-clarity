# CarbonClarity — Build Approach & Considerations

*Deliverable write-up (1–2 pages). Pre-filled where determinable; `[fill after building]` where real results are needed.*

## How we approached it
We started from the scored bar, not the feature list. The brief rewards a **working backend with real processing**, **thoughtful tech integration**, **showroom UI/UX**, **before/after business impact on screen**, and a **self-explanatory executive walkthrough** — and explicitly penalizes hardcoded responses and production gold-plating. Scenario D's "wow" is acknowledged to be lower than the other scenarios, so we deliberately concentrated all polish on a single hero — the **decarbonization scenario planner** — and made the supporting emissions math genuinely correct so the demo survives the judges changing inputs live.

We scoped to the customer's actual unmet need from the brief: a $3B Singapore manufacturer with 12,000 tCO2e Scope 1+2, an estimated 108,000 tCO2e Scope 3, a board target of 40% reduction by 2030, and a $10M three-year budget — and *no way to model which investments move the needle, or in what sequence.* Everything we built answers that one question on screen.

Day order followed the gates: Day 1 a real computed emissions value end-to-end; Day 2 the full Scope 1+2 engine + baseline dashboard with live-changing outputs; Day 3 the scenario engine + AI board summary + all views; Day 4 the compliance report, the before/after, and one-command CDK deploy validated from a fresh clone; Day 5 write-ups, recording, and buffer.

## Technology chosen + why
- **React + TypeScript + Vite + Tailwind + Recharts** — fast to build, touchscreen-friendly sizing, and Recharts gives us the live-bending trajectory line with a dashed target reference cheaply.
- **Python on AWS Lambda behind API Gateway HTTP API** — the emissions and scenario engines are naturally pure functions; serverless means ~$0 idle and a one-command deploy, which itself reads well for a sustainability product.
- **Live language model for the board narrative** — the audience is a board, so we turn the engine's numbers into the language a CEO would present, generated by an actual LLM *at request time* and grounded strictly in the computed scenario result so it cannot drift from the real numbers. Two providers behind one interface: **Amazon Bedrock (Claude, `anthropic.claude-sonnet-4-6`)** when AWS creds are present; otherwise a **keyless public LLM endpoint** so the AI runs live with *zero* credentials. We stream the response so the panel fills in live; responses are cached by prompt and degrade to a grounded narrative only if the model is unreachable.
- **AWS CDK (Python)** — infrastructure as one command, region-portable (Singapore primary, us-east-1 fallback for Bedrock access).
- **Synthetic data only** — 200 buildings across 15 countries, deterministically generated (seed=42), with country grid factors, fuel factors, REC coverage, and currencies. No real customer data, no secrets in the repo.

## Tradeoffs given the time box
- **Scoped hard to the scenario planner.** We treated the planner as the one thing that must be a 5 and accepted rough edges off the demo path. The compliance report is coherent but not exhaustive; we'd rather have one flawless hero than three mediocre views.
- **Scope 3 is estimated, and labeled as such.** The brief itself frames Scope 3 as "estimated 108,000 tCO2e." We use a spend-based intensity estimate (annual spend × intensity factor) rather than modeling supply-chain categories, which would have consumed days for little demo lift. It is clearly marked "estimated" on screen to stay honest.
- **Emissions factors are illustrative sample values.** Real per-country/per-fuel factors shift with vintage and methodology; we used plausible public-style values and label the data as synthetic. The *math* is real; the *factors* are sample.
- **Linear deployment ramp in the scenario engine.** Real abatement curves are lumpy (projects commission in steps). We used a linear ramp to 2030 — readable, instant, and defensible for a planning prototype — and noted it as a simplification.
- **No tests/CI/monitoring/multi-env.** Explicit anti-criteria; we spent zero effort there and put the time into the demo path.

## Interesting challenges
- **Getting the emissions math right and explainable.** The genuinely hard part of carbon accounting is **location-based vs market-based Scope 2**: location-based uses the country grid average; market-based applies RECs first and then a residual-mix factor, so a site with a green-power contract reports *lower* market-based emissions. We implemented both, surfaced the difference on the dashboard, and made the supplier-switch lever move exactly that number — so the audience can *see* why market-based accounting matters, not just hear it. Unit conversion (kWh ↔ MWh ↔ GJ, fuel volume → energy) and REC allocation are table-driven so a judge editing a value flows cleanly through to the result.
- **Landing the hero numbers exactly.** Tuning the synthetic generator so 200 buildings aggregate to precisely 12,000 tCO2e Scope 1+2 and 108,000 tCO2e Scope 3 — and so the seeded lever combo lands at ~41% reduction, under the $10M budget — took iteration. We pinned a `hero_portfolio.json` so the demo always opens on compelling, on-brief numbers.
- **Making the planner feel alive without flicker.** Debouncing slider input, animating the trajectory and budget meter, and keeping the target line fixed so the "crosses below target" moment reads instantly.
- **Grounding the AI so it can't lie.** Passing the exact scenario result into Claude and constraining it to those numbers — board-credible prose that always matches the chart.

## Production-realism iteration
After the engine and hero were solid, we did one pass to make the cockpit read like something a real sustainability/finance team works inside — all of it frontend presentation, with the backend untouched.
- **Singapore framing + SGD.** We named the entity **Meridian Industries**, an SGX-listed manufacturer, and present every figure in **SGD** for a Singapore board: budget **S$13.5M** (≈ US$10M), revenue **S$4.1B** (≈ US$3B). The backend still computes in USD/native units; SGD is a display-time conversion (×1.35) isolated in `frontend/src/domain.ts`, so the math the judges test is unchanged.
- **Light/dark theme toggle (one palette, two paths).** A new `frontend/src/theme.ts` holds a single `PALETTES` source of truth (light default) and writes it onto `<html>` as CSS variables — hex *and* `-rgb` channels. Tailwind utilities and `index.css` read those variables; Recharts can't use Tailwind classes, so it reads a live `chart` Proxy that returns the current palette. One sun/moon toggle + a re-render repaints the whole app, charts included — the same colour decisions flowing down two rendering paths.
- **Disclosure & assurance register.** A new `frontend/src/components/DisclosureRegister.tsx` (data in `domain.ts`) at the foot of **Compliance & Reporting** lists every framework Meridian reports against — GHG Protocol, SGX Sustainability Report, GRI 305, ESRS E1, IFRS S2 — each with an Assured/Filed/In review/Draft status and its legacy manual effort. It is the system-of-record / audit-trail beat and carries the pitch hook: fragmented multi-framework reporting *is* reporting risk that one engine collapses. Static, hand-authored narrative context.
- **Reporting-period switcher.** The header switches reporting period (FY2025 Q1 live; prior periods come from the register) — the entity/period chrome a real cockpit has, kept honest (only the current cycle is live).
- The full executive read-through lives in **DEMO_SCRIPT.md**, rewritten as a CEO/CFO pitch (problem → stakes → live proof → business case → pilot ask).

## What we'd do differently with more time
- Category-level Scope 3 (purchased goods, logistics) instead of a single spend-based estimate.
- Real, versioned emission factor sets (e.g. national grid factor libraries) with methodology toggles.
- Marginal-abatement-cost ordering: auto-sequence investments by $/tonne to *recommend* the optimal path, not just model a chosen one.
- Export the compliance report to a real GHG Protocol / ESRS-formatted PDF.

- **Live AI verified:** the board summary is genuinely **model-generated** — verified end-to-end via the keyless LLM, `/summary` returns `source:"llm"` with prose grounded in the real scenario numbers (e.g. "41.0% reduction, US$8.7M committed, exceeds the 40% target, 7,080 tCO₂e residual, deploy the US$1.3M remainder on battery storage"). Default path needs **no AWS creds**; `USE_BEDROCK=1` streams from Bedrock/Claude with the same SSE contract. The free endpoint rate-limits bursts, so hero scenarios are pre-warmed into cache (instant, reproducible) and any unreachable call degrades to the grounded narrative.

Cached narratives for hero/zero/max combos in `data/summary_cache.json` plus a per-prompt LLM disk cache. **Verified:** SSE delivers model-generated word-deltas through the Vite proxy and direct.
